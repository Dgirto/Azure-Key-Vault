¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic leer secretos, llaves y certificados de Azure Key Vault: obtener el valor de un secreto, listar los secretos disponibles (metadatos), y obtener los metadatos de un certificado.

Este conector puede exponer valores reales get_secret devuelve el valor real del secreto en texto plano. get_certificate solo devuelve metadatos, nunca la clave privada.
OperaciónQué hace
keyvault.get_secretObtiene el valor de un secreto
keyvault.list_secretsLista los secretos disponibles (metadatos)
keyvault.get_certificateMetadatos de un certificado (sin clave privada)

Prerrequisitos

  • Un Azure Key Vault ya creado, con al menos un secreto.
  • Acceso a Azure Active Directory para registrar una aplicación (Service Principal).

Configuración en el fabricante

  1. Registra una aplicación (Service Principal) dedicada.

    En Azure AD → App registrations → New registration. Generá un Client Secret en "Certificates & secrets".

  2. Otorgá acceso al Key Vault con mínimo privilegio.

    Si el vault usa RBAC: asigná los roles "Key Vault Secrets User" y "Key Vault Certificate User" al Service Principal, con alcance limitado a ese vault. Si usa Access Policies clásicas: otorgá permisos Get y List sobre Secrets y Certificates.

  3. Anotá los identificadores necesarios.

    Tenant ID, Client ID, Client Secret, y la URL del vault (Overview → Vault URI).

Permisos requeridos

PermisoPara qué sirve
Key Vault Secrets User / Get+List sobre SecretsObtener y listar secretos
Key Vault Certificate User / Get+List sobre CertificatesObtener metadatos de certificados
Nota No se otorgan permisos de escritura (Set, Delete, Purge, Recover) ni de administración de acceso.

Configuración en Ruvic

Entrá a Settings → Conectores, buscá Azure Key Vault y pulsá Configurar. Completá Tenant ID, Client ID, Client Secret y la URL del vault.

Probar conexión — la plataforma listará secretos (solo metadatos) para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Listame los secretos del Key Vault (solo nombres)."

    El agente debe devolver el listado real de nombres.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o sin permiso suficiente"Client Secret vencido/rotado, o falta el rol RBAC / access policy necesario sobre el vault.
"El secreto/certificado no existe en el vault"Nombre mal escrito, o el recurso está en otro Key Vault distinto al configurado.
"No se pudo conectar al Key Vault" (timeout)URL del vault incorrecta, o el vault tiene restringido el acceso de red (firewall/red privada) que bloquea a Ruvic.
El conector aparece "Sin configurar" tras guardarAlgún campo obligatorio quedó vacío. Completá Tenant ID, Client ID, Client Secret y URL del vault.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar o borrar secretos?

No. El Service Principal solo tiene permisos de lectura (Get/List); el conector no expone ninguna operación de escritura.

¿Dónde queda guardado el Client Secret?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales

Los Client Secrets de Azure AD expiran automáticamente (según lo configurado, hasta 24 meses). Generá uno nuevo antes del vencimiento y actualizalo en el formulario.

¿Qué hago si el Client Secret se compromete?

  1. Eliminá el Client Secret comprometido en Azure AD → App registrations → Certificates & secrets.
  2. Generá uno nuevo y actualizalo en el formulario.
  3. Revisá los logs de acceso del Key Vault (Diagnostic settings) por actividad inesperada.
Buenas prácticas Usá un Service Principal dedicado con acceso limitado a un único vault; nunca uses una identidad con permisos de administración global; y evitá mostrarle al usuario el valor de un secreto salvo que lo pida explícitamente.
